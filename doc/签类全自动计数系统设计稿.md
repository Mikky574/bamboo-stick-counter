# 签类全自动计数系统设计稿

日期：2026 年 10 月 7 日
状态：技术设计，尚未完成新方案实现与效果验证
适用项目：bamboo-stick-counter

当前工作优先级为模型与算法验证，详见 [签类计数模型与算法框架设计](签类计数模型与算法框架设计.md)。本文中的页面和服务流程作为后续集成约束；CountGD++ 优先作为通用模型对照，不预先确定为最终生产模型。

## 1 产品目标

客户上传或拍摄一张图片，系统自动识别竹签、棉签等支持范围内的签类物品，输出逐根编号与数量。客户不选择品类、不框选示例、不输入文字提示、不调整筛选强度。所有目标识别、示例生成、分块、候选验证与去重在系统内部完成。

对外采用统一交互，对内允许模型根据图像内容和目标尺寸自动处理。统一效果是同一套经过验证的运行策略，而不是要求所有图片使用同一种尺寸或同一个分块方式。任何阈值和策略都在开发阶段校准、在独立测试集上验收，发布后固定，不允许按客户图片临时调参。

一期聚焦成束或整齐排列、从一侧观察的签类端面计数。竹签端面和棉签棉头虽然外观不同，但共享“每个可见实例对应一根物品”的计数结构。双头棉签散放、两端同时出现、严重交叉遮挡的整根计数属于另一种实例关联任务，不能直接用棉头数量替代根数。

## 2 客户页面

页面只保留以下主要内容：

- 上传图片或拍照入口；图片加载后自动开始识别。
- 处理状态，如“正在识别”“正在核对密集区域”。
- 完成后的数量、原图编号叠加和结果下载。
- 无法可靠识别时的具体拍摄提示，如“端面未完整入镜，请重新拍摄”。

页面不显示品类选择、示例框操作、模型选择、阈值、NMS 或强度滑块。内部识别出的类别可作为结果说明，但不要求客户确认后才能运行。

成功结果示例：“识别完成，共 N 根”，同时显示每根对应的标记。未通过可靠性检查时显示“暂无法可靠计数，请重新拍摄”，不把未经验证的数字包装成准确数量。开发调试页面可以保留候选点与参数，须与客户页面分离。

编号、数量、PNG 与 JSON 来自同一份最终实例列表。导出内容记录模型版本、图像尺寸、计数区域、最终坐标和处理状态，以便复现。

## 3 当前实现的问题与证据

当前项目通过 GeCo2 提取示例区域的外观和尺寸，预测中心响应及框。model_counter.py 再按相对最高响应进行阈值过滤，默认不使用框 NMS，关闭 SAM 掩膜细化。界面与 API 都依赖当前图片中的示例框。

内置竹签图已复现如下结果，位置指默认编号 3 的右侧、8 的上方：

| 配置 | 输出数量 | 指定漏点 | 解释 |
| --- | ---: | --- | --- |
| 阈值 0.33，无框 NMS | 96 | 缺失 | 该端面的候选相对响应约为 0.1844，被过滤 |
| 阈值 0.20，无框 NMS | 97 | 仍缺失 | 总数增加不代表补回正确目标 |
| 阈值 0.18，无框 NMS | 106 | 出现 | 同时出现重复预测 |
| 阈值 0.18，框 NMS IoU 0.5 | 98 | 出现 | 重复点减少，仍不代表逐根正确 |

诊断脚本及结果在 outputs/diagnose_threshold.py、outputs/threshold_diagnosis.json。该图尚无独立逐根人工真值，96、97、98 都不能直接作为正确数量。

这说明仅调一个全局响应阈值无法同时解决弱响应漏检和重复预测。现有相对响应不是校准概率；模型内部还存在局部极大值筛选，部分遗漏也可能发生在候选生成阶段。取消滑块必须伴随识别策略改造。

## 4 论文依据与选型

### 4.1 CountGD++ 作为免人工示例的主要研究基线

CountGD++，CVPR 2026，支持根据文字提示初次检测，选择高分框作为伪示例，再将文字和伪示例输入模型进行第二次推理；也支持正负提示和外部示例。[论文及方法说明](https://arxiv.org/html/2512.23351v2)

本项目借鉴其自动示例机制。文字提示由系统根据自动识别结果和预设目标策略生成，不由客户填写。自动类别识别与计数区域定位是本项目额外模块，不能宣称 CountGD++ 已经实现无任何目标定义的签类全自动计数。

论文实验统一采用 0.23 的置信阈值；该值只能作为基线起点，不能直接替换当前 GeCo2 的相对响应阈值。两个分数的含义不同。[论文实验设置](https://arxiv.org/html/2512.23351v2)

官方代码和权重可用，但普通 Gradio 演示未集成伪示例和自适应裁剪；需要从测试流程提取相关逻辑。官方安装流程面向 Linux、CUDA，包含编译组件。部分复现实验使用预先生成的增强裁剪图及合成示例，不能把这些条件下的论文结果当作新上传图片上的直接效果。[官方仓库](https://github.com/niki-amini-naieni/CountGDPlusPlus/)

### 4.2 DAVE 支持先检测再验证的设计

DAVE，CVPR 2024，采用先生成高召回候选、再验证并移除离群误检的思路。本项目将“候选生成”和“最终实例确认”分开，避免低阈值候选直接进入最终数量。[论文](https://openaccess.thecvf.com/content/CVPR2024/html/Pelhan_DAVE_-_A_Detect-and-Verify_Paradigm_for_Low-Shot_Counting_CVPR_2024_paper.html)

这是设计依据，不意味着直接添加一个启发式过滤器就能复现 DAVE。验证模块需要明确训练或校准方式，并通过消融实验确认收益。

### 4.3 PseCo 支持点定位与轮廓证据结合

PseCo，CVPR 2024，结合点定位、SAM 分割及 CLIP 语义分类进行计数，针对小而密集目标的定位和区分提出专门处理。[论文](https://openaccess.thecvf.com/content/CVPR2024/html/Huang_Point_Segment_and_Count_A_Generalized_Framework_for_Object_Counting_CVPR_2024_paper.html)

本项目借鉴局部轮廓证据验证实例的思想。分割只作为证据之一：棉头粘连、模糊边界可能造成合并，不能假设 SAM 的每个掩膜天然对应一根签子。

### 4.4 专用竹签研究支持分块与边界处理

MobileNetV3 With CBAM for Bamboo Stick Counting，IEEE Access 2022，直接研究密集竹签计数，使用分块与边界处理。[出版方页面](https://ieeexplore.ieee.org/document/9775932/)

它提供场景相关的工程参考，但属于应用期刊论文，不称为顶刊。其场景、指标与数据条件不能直接外推为棉签或本项目逐图完全正确的比例。

### 4.5 专用点定位作为后续训练路线

P2PNet，ICCV 2021，通过点预测和训练时的一对一匹配学习实例定位。本项目可参考该监督方式，训练覆盖多个签类的端面定位模型。[论文](https://arxiv.org/abs/2107.12746)

现成人群权重不能直接视作竹签或棉签权重，一对一训练也不保证推理零重复。需要签类数据训练和独立评估。

## 5 全自动识别架构

流程：图片质量检查 → 签类区域及外观识别 → 初次候选生成 → 自动示例选择 → 多尺度计数 → 候选验证 → 实例关联与去重 → 自动复检 → 结果发布。

### 5.1 图片质量与场景检查

检查清晰度、曝光、端面是否入镜、目标是否足够大、是否存在严重遮挡，以及是否属于支持的端面拍摄场景。初期可以结合简单图像质量特征和训练的场景分类器，具体判定边界由验证集确定。

空图、无签类物品、画面不支持计数与可靠的零根结果要区分。图片不满足条件时输出具体原因，不进入无限复检。

### 5.2 自动发现目标与计数区域

建立签类候选区域定位模块，自动寻找成束或排列的端面区域，并识别裸露木质端面、棉质端头等外观组。一个模型共享特征，允许内部使用不同外观处理分支；客户交互保持一致。

初期以系统维护的目标描述集合和签类区域检测器进行候选发现，描述应针对可见端面或棉头。用实际图像验证提示是否会把整根杆体或背景纹理当成目标，不假设语言模型天然理解所有工业拍摄角度。

混合品类照片先按区域确定支持范围。若各区域均通过验证，可汇总根数；存在两端关联或未知目标时不强行汇总。不要求客户选择类别来消除模型歧义。

### 5.3 自动选择示例

优先采用 CountGD++ 的初次预测生成伪示例。示例候选需满足：目标完整、非画面截断、与邻居有足够可区分证据、尺寸合理、符合签类区域。

选择覆盖不同尺寸、亮暗与位置的少量示例，避免只选最亮的一组。初始使用最多三个代表实例，数量与选择策略在验证集上确定。不能先假定固定圆度适用于棉签。

只有自动示例通过检查才用于后续推理。初次预测错选背景会使错误传播，因此伪示例选择需要单独统计成功率。预设迭代上限，例如最多两次示例更新；总数收敛仅作为稳定性证据。

### 5.4 整图与局部多尺度计数

先进行整体识别，再根据自动估计的目标尺寸选择需要复检的密集区域。在原始图像上裁剪并保留足够上下文，采用带重叠的分块推理，全部坐标映射回原图。

每个分块包含用于识别的上下文区和用于结果归属的核心区。结合核心区归属及跨块实例关联处理边界重复。端面截断预测应由邻块提供完整证据，不能直接把截断候选当作新实例。

首版使用普通缩放和原始分辨率裁剪。AI 超分辨率不作为必要步骤，避免生成的纹理被误当成端面结构；若引入，必须单独评估是否改变实例数量。

### 5.5 候选验证

验证每个候选是否是独立签类端面，证据包括局部图像特征、类别与区域一致性、尺寸范围、可见轮廓，以及多尺度预测一致性。

优先评估可训练的局部验证器：标注真实端面、背景误检、同一端面的重复预测和邻近不同端面。对棉签保留不规则形状和粘连样本，避免硬性圆形过滤。

模型响应低不直接判为背景；响应高也不直接判为正确。联合决策在开发阶段固定，必须证明能够保留已知弱响应真目标并排除重复。

### 5.6 实例关联与去重

去重的目标是把同一物理端面的多个预测归并为一个实例。联合参考中心距离相对端面尺寸、预测区域重叠、局部特征和轮廓证据，不使用绝对像素距离作为唯一依据。

同一端面预测合并；相邻不同端面即使框重叠也保留。谨慎处理链式关联，避免 A 接近 B、B 接近 C 就把三个真实端面合并。棉头粘连不能单纯按一个连通区域计一根。

框 NMS 保留为对照基线。是否使用分割、学习的实例关联器或尺寸归一化规则，由独立实验决定，而不是在设计阶段声称其中任何一种已经解决问题。

### 5.7 自动复检与发布判定

复检触发条件包括低证据候选、区域内明显未解释的端面结构、不同尺度的实例列表冲突和分块边界不确定性。复检后重新关联实例，而不是直接累加新增点。

可靠性基于图像质量、候选验证结果与实例一致性校准。多次预测相同、平均响应高、总数不再变化都不能单独视为准确证据。

通过发布条件才输出完成结果。无法可靠处理的图像输出重拍原因。未校准前不显示“99% 准确”或类似概率描述。

## 6 数据与验收

### 6.1 数据范围

先采集真实业务照片，覆盖竹签、木签和棉签；如果需要扩展到牙签、塑料签等，必须加入相应数据和验收。覆盖稀疏与密集、粘连、尺寸变化、浅深背景、曝光变化、倾斜、包装边缘和多个束。

单独收集无目标、圆形纹理、棉球、杆体侧面、双头散乱棉签、严重模糊或遮挡等负例和不支持场景。公开通用计数数据可用于初始化或辅助训练，不能替代业务验证集。

标注每个可见目标中心、物品类别、图像总数、计数区域及遮挡状态；选择一部分困难样本补充框或实例轮廓。人工标注由第二人复核，争议图不强行作为准确真值。

第一轮建议每个主要品类收集约 100–200 张照片作为可行性评估起点，后续规模根据学习曲线和错误覆盖决定。这是采集预算建议，不是论文证明的数据需求。以拍摄批次、物品批次和设备划分训练、验证和测试，禁止同一照片的裁剪或相近连拍泄漏到不同集合。

### 6.2 验收指标

| 指标 | 用途 |
| --- | --- |
| 每图根数完全正确率 | 主指标；分别报告竹签和棉签及困难场景 |
| 漏检率与误检率 | 防止数量相互抵消掩盖问题 |
| 重复实例比例 | 验证去重是否有效 |
| 平均绝对计数误差及误差分位数 | 展示平均表现和严重失败 |
| 自动完成率与拒绝率 | 防止拒绝大量难例换取高正确率 |
| 通过发布的结果中数量正确率 | 评估可靠性策略，并报告覆盖率 |
| 推理延迟 P50、P95 和峰值内存 | 判断部署是否符合客户等待时间 |

完全正确的验收需同时检查实例定位，不能仅判断总数相等。点匹配容差依据实际端面尺寸确定，并对各方案统一使用。

正式性能门槛待真实样本基线确定后冻结。若业务提出例如“至少 99% 的完成结果根数完全正确”，该数值应作为验收目标，连同自动完成率下限和足够测试样本量一起验证，不能当作现有性能承诺。

### 6.3 对照与消融

依次比较当前 GeCo2、CountGD++ 系统预设提示、加入自动示例、加入分块、加入候选验证、加入实例去重和复检后的效果。记录每项对漏检和重复的独立贡献，以及耗时增加。

内置竹签图用于回归定位指定漏点和重复点，不作为泛化主证据。完整业务测试集必须同时包含棉签。所有对照在冻结配置下执行，不逐图选择最有利结果。

## 7 项目改造与部署

现有 Flask 服务、Canvas 编号和导出功能可以保留。新增独立的自动计数入口，建议为 /api/count-auto，接收图片，不要求 engine、exemplars、threshold 或类别参数。

内部建议拆分质量与场景检查、区域识别、自动示例、多尺度推理、候选验证、实例关联和结果发布模块。现有 /api/count 及手动设置保留在开发环境用于回归和比较，不用于客户主流程。

结果结构至少包含 status、count、points、regions、reason、elapsed_seconds、model_version 和 pipeline_version。成功状态给出 count；需重拍状态不给出作为最终结果的数量。图片无支持目标与计数失败分别编码。

较长处理使用任务提交与状态查询，设置时间预算、并发限制和明确的失败状态。客户页面不因请求超时而丢失任务。原图与结果的存储期限按产品部署方式确定。

当前本机为 Windows、AMD Radeon 780M，已配置 Python 3.11 CPU 环境。GeCo2 的一次内置图首次调用约 8 秒，不能外推到更重的 CountGD++ 或多轮复检。CountGD++ 的官方 Linux/CUDA 安装流程在此机器尚未验证。

研究评估优先使用独立 Linux/NVIDIA GPU 环境；本机继续运行页面和现有基线。若业务要求图片完全本地处理，最终选择可部署的轻量签类定位模型并实测 CPU 性能。服务器方案与本地方案保持相同客户交互，数据传输方式需在确定部署要求后选择。

## 8 实施顺序与决策门槛

第一阶段建立逐根真值、明确端面拍摄范围，复现竹签和棉签的当前错误。产物为标注规范、冻结测试集和基线报告。

第二阶段建立 CountGD++ 基线，并实现系统内部提示与自动示例，检验免客户操作是否在主要品类成立。自动类别与区域识别必须独立验收。

第三阶段实验分块、候选验证和实例关联。优先解决实际错误类型，每项增量都做消融，避免不断堆叠推理却没有净收益。

第四阶段根据效果与耗时决定保留通用模型，还是训练多品类签类端面定位模型。后者使用共享特征和点定位监督，困难局部可增加实例分割辅助监督；通过学习消除误检和重复，而不是积累逐图阈值规则。通用模型预测可以辅助标注，但必须人工校正后才作为训练真值。

第五阶段接入客户自动页面，移除客户调参入口，冻结完整策略，并对独立业务测试集进行上线验收。

当前推荐研究路线为 CountGD++ 自动伪示例与签类区域识别，加上经实验筛选的分块和实例验证。专用轻量多品类模型作为效果或部署不达标时的下一步。这是待验证的技术选择，不是已达成的正确计数能力。

## 9 范围与重要限制

完全不可见的签子无法仅靠单张照片确定实际根数。成束端面计数需要每根有可见证据；业务如要求不满足该条件仍准确计数，应增加拍摄视角或改变物品摆放方式。

竹签与棉签共享计数框架，但材质、形状和粘连机制不同，必须分别评估；统一页面不等于免除跨材质训练和测试。
