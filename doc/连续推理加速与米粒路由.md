# 连续推理加速与米粒路由（2026-10-18）

## 当前行为

网页“自动选择·推荐”：竹签/棉头走CountGD++，米粒仅在用户确认分散、背景简单时走快速颗粒算法。粘连场景自动模式返回明确错误，避免把连通区域数当米粒数；可显式选GeCo2等对照并人工复核。只改对象为米粒，不再默认继续使用通用文字检测。

CountGD++没有初检目标时返回meta.diagnosis=no_initial_exemplars；前端显示“—”及失败原因，不把0解释为确定没有目标。通用模型在现有米粒图的initial_count和pseudo_exemplar_count均为0，说明自动示例链未建立，而不是米粒在图中不存在。

GPU连续模式每次只缓存模型运行时；不缓存并直接复用上一张图的预测、示例或人工真值。仍保留两轮推理、相同阈值和输入尺寸。API默认不缓存，网页选择keep_warm=true且device=cuda才启用。空闲120秒后自动结束本项目worker树；/api/release-model可主动释放，任务进行中拒绝释放。切换GeCo2或非缓存请求前释放旧缓存，避免两种大型模型叠加。

## GPU真实HTTP实测

RTX4090。原始结果在outputs/runtime_speed_validation/，以下为一次实测，不是速度保证：

| 用例 | 数量输出 | 整次HTTP用时 |
|---|---:|---:|
| 棉头GPU连续模式首次请求 | 107 | 12.271秒 |
| 相同棉头图，复用模型 | 107 | 0.472秒 |
| 换成木签图，复用模型 | 99 | 0.791秒 |
| 通用文字模型处理米粒 | 0，识别失败 | 0.289秒 |
| 分散米粒，自动路由颗粒算法 | 30 | 0.033秒 |
| 兼容原单请求GPU模式 | 107 | 9.077秒 |

首次模型内部加载耗时9.263秒，首次初检0.817秒、第二轮0.212秒；重复请求加载0秒，两轮分别约0.193和0.195秒。之前页面只显示worker部分计时，遗漏进程和依赖导入。本版同时记录父进程total_elapsed_seconds、客户端request_elapsed_seconds与模型各阶段时间，页面使用本次完整请求用时。

棉头/木签数量输出与本轮改动前相同，尚无独立准确率评测；缓存只改善速度，不能自动修正漏检。分离米粒30与现有单图目视初核一致；粘连米粒图仅4个连通域，不是4粒。

## 检查

verify_runtime_rice.py的8项轻量测试已通过：真实米粒API、粘连限制、保存的失败原因、缓存参数转发、状态与释放端点、页面控件及错误提示。另做真实GPU冷/热、跨图片复用、失败诊断、单次兼容和手动释放检查。Windows常驻管理器用轻量多层子进程验证手动/空闲释放，均结束自己创建的完整进程树；错误、坏协议、超时和忙时保护也已测试。

## 参考图数量

当前自动模式需要用户提供0张参考图；每张待识别图临时自动选最多3个对象。未来固定模板模式可先试平头、尖头、棉头各1张参考照片，每张选1–3个实例，再根据不同光线、材质和尺寸的跨图实测补充。这个数量是起步实验安排，不是能保证准确的通用门槛。模板数量不按待处理图片张数增长。

CountGD++官方提供外部正/负示例复用参数，但本地worker尚未接入固定模板或负示例：[官方test_dataset.py](https://github.com/niki-amini-naieni/CountGDPlusPlus/blob/main/test_dataset.py)。本轮没有训练新模型、降低输入分辨率或删除第二轮推理。
