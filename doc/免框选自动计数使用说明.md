# 免框选自动计数：已搭建的验证方案

2026-10-17。本版为可运行的计数与预标注原型，尚未达到稳定准确计数的生产验收标准。

## 使用

本机环境与官方 CountGD++ 权重已准备好。运行项目根目录 `start.ps1`，浏览器访问 http://127.0.0.1:5080 。

选择“自动选择 · 推荐”，上传图片，设置计数对象后点击“自动识别并编号”。竹签和棉头使用CountGD++；米粒需先明确分散/粘连，分散时走快速颗粒算法，粘连时提示不支持可靠的一键计数。对象选择是业务预设，不是自动识别品类；不需要文字输入或手动示例框。

2026-10-18更新：网页默认选择GPU和连续识别；独立CountGD++子进程首次加载模型，后续请求复用，空闲120秒自动释放，也可点击“立即释放模型显存”。关闭连续模式后每次结束退出。API/CLI默认仍为CPU单次推理，只有显式device=cuda且keep_warm=true启用缓存。PyTorch仍限制4个CPU线程；首次GPU加载前要求至少8GiB空闲显存。网页服务不直接导入大型模型。Windows释放仅结束本项目所创建的worker进程树。

GeCo2 人工示例对照也改为独立子进程，API 不再跨请求缓存模型；原命令行 model_cli.py 仍为一次性运行程序。

## 流程

系统预设目标描述 → CountGD++ 文字初检 → 从预测中选择最多 3 个自动示例 → 同图第二轮计数 → 框中心转原图坐标 → 输出逐点编号。

免框选后端只读取上传图片、对象类型和模型资产，不读取样本的人工示例坐标或人工真值。响应记录manual_exemplars=false、自动示例、文字描述、设备和阈值；worker_exited区分单次退出与连续模式，cache_reused表示是否复用模型。每张图的示例重新计算，不跨图积累为训练集。

这不是官方论文完整评测配置：不生成合成示例，不调用外部付费超分服务，不做自适应裁剪；最终预测默认不启用框 NMS。自动示例选择有 IoU=0.5 的去重。所有实例化的模型参数严格加载，唯一排除的 feature_map_encoder 分支没有被官方演示架构实例化，且官方训练模型的相应 forward 调用已注释。

## 实测结果与局限

CPU 运行每张约 38–68 秒，包含模型加载和两次推理。结果写入 `outputs/automatic_validation/report.json`。

| 图片 | CountGD++ 免框选预测 | 真值/结论 |
| --- | ---: | --- |
| 原项目密集竹签 | 97 | 没有完整独立人工真值；不能宣称数对 |
| 手持竹签 | 5 | 人工单人初标 18，漏检明显 |
| 密集棉头裁剪 | 116 | 粘连明显，数量未核验 |
| 分离米粒 | 0 | 单图目视复核 30，通用文字模型失败 |

因此，接入 CountGD++ 并没有自动解决领域准确率问题。当前接口与自动提示链路已跑通，但不能作为可靠出库计数系统。界面保留“自动颗粒计数（分离米粒）”，该传统分割在分离米粒图得到 30；接触/重叠米粒不能据此保证正确。

原手持竹签的 GeCo2 18 个匹配结果依赖人工提示，不能当作本免框选后端的成绩。

## 批量预标注

```powershell
.\.venv\Scripts\python.exe auto_cli.py <图片或文件夹> --category bamboo --device cpu --output outputs/auto_labels
.\.venv\Scripts\python.exe auto_cli.py <米粒图片> --category rice --separated-grains --output outputs/rice_labels
```

每张图导出预测 JSON、编号 JPG、LabelMe 点标注 JSON及原图副本。LabelMe JSON可用于兼容的标注编辑器复核；尚未实测外部 GUI 导入。导出文件标明未审核预测，不伪装为人工真值。人手修正后的标注应另行保存并标识审核状态，再用于训练。

## 换机器准备

```powershell
.\setup_auto.ps1
# 如需代理，仅本次设置：
.\setup_auto.ps1 -Proxy http://127.0.0.1:10090
```

该脚本为免框选后端创建 `.venv-countgdpp`；现有网站仍使用原项目 `.venv` / requirements.txt。环境继承系统可用的 PyTorch 包，兼容的 transformers/hub 等依赖安装到项目专用环境，不修改系统包。脚本已进行语法检查；当前机器的实际环境通过相同安装步骤准备，未做第二台干净机器端到端重装验证。

官方仓库与权重在本地保存，未把 1.25 GB checkpoint 纳入 Git。源码固定版本与 SHA-256 见 `models/countgdpp-provenance.json`。Windows 不需要编译 CUDA 扩展，使用作者已有的 PyTorch deformable-attention 实现。

## 复现检查

```powershell
.\.venv\Scripts\python.exe verify_auto.py
.\.venv\Scripts\python.exe verify_model.py
```

verify_auto.py 测试四张真实图片的真实免框选推理、手动示例被忽略、坐标合法、子进程退出和参数校验，并记录准确率缺口；不把得到一个数量当准确率通过。

## 推荐下一步

先选清晰端面这一窄场景，建立独立真实照片测试集。使用通用模型提供预标注初稿，人工修正后训练专用点定位/检测模型。当前手持图说明文字模型会把整根杆体当目标，后续训练要明确“可见端面一个点”的定义。对背景简单的分离米粒保留低成本分割，对粘连棉头另收困难样本。只有测得逐实例改进，才增加分块、边界分支或二次验证。
