# 昆虫个体计数：当前结果与可选方案

## 当前实现与已知错误

八类场景分类器未训练昆虫，不能因其接受“米粒”就确认目标是米粒。当前增加的是自动深度路径空结果后的单次语义重选，以及统一 `insects` / `insect` 目标；没有增加蝴蝶、甲虫等物种分类权重，没有训练新模型。网页仍只需图片和一个识别按钮。

当前 CountGD++ 的初始文本检测和自动示例能够给出昆虫候选，但不能保证每个框都是一个完整个体。独立核对本地蝴蝶标本图发现：一片顶部翅膀被重复检测，小蓝蝶漏检；返回10候选与人工总数相同仍不算正确。改成通用 `insect` 提示也未解决这两个问题。9个固定切图虽能找到蓝蝶，同时产生大量高分翅膀片段；分数、框包含、简单NMS或跨切图重复支持都不足以可靠区分。生产流程没有加入这些切图融合。

结果继续标为 `insect_candidates`、`review_required:true`、`count_is_total:false`。这只解决了不能自动进入昆虫候选路径的问题，不是逐只准确计数验收。

## 优先验证：不分物种的实例分割

[FlatBug 官方仓库](https://github.com/darsa-group/flat-bug)提供针对陆生节肢动物的统一检测和实例分割模型、现成权重与多尺度切图推理，主要面向俯视图片。它基于训练过的 YOLOv8 分割模型，不要求为每种昆虫重新建类别。模型输出每个个体的掩膜，比仅凭一个重叠矩形核对个体提供更多信息。

建议先以独立模型环境、同一批原图验证现成权重，保留每个掩膜、点位、漏检和误检清单；验证达标后再接入现有图片按钮。当前尚未下载或运行 FlatBug，不能说它在本项目更准。其目标包含蜘蛛等非昆虫，产品应明确是数所有节肢动物还是严格数昆虫。

[FlatBug 论文](https://doi.org/10.1111/2041-210x.70249)也指出相互嵌套个体仍有去重困难，正对应小蓝蝶覆盖大黑蝶的场景。换成分割不能自动保证零漏检或零重复。

## 需要训练时：每只一个点，不必标精确框

如果主要输出点位和数量，可以训练单类昆虫点检测模型：在每个可辨认的个体胸部／虫体中心标一个点，完整翅膀不额外标点，翅膀片段、标本针、文字与背景作为负例。不同大小、花色和物种共享“一个虫体实例”的标注口径。遮挡但可明确区分的个体保留；完全不可见或无法确认的个体不凭空推断。

[P2PNet 官方论文](https://arxiv.org/abs/2107.12746)提出点监督计数和定位以及一对一匹配学习，可作为这种训练设计的参考。其原任务是人群，现成人群权重不能直接视为昆虫计数模型；需要昆虫点数据训练并在未参与训练的照片上验证。一对一匹配有助于学习“一只一个点”，不保证新图片永远没有漏检或误检。

另一种免逐物种列举的候选是 [SAM 3 官方实现](https://github.com/facebookresearch/sam3)，支持用文字或示例匹配多个实例并输出掩膜。它仍需实际图片验证；官方权重需要申请访问，运行环境与当前 CountGD++ 不同。当前未下载、未安装或接入，不自动覆盖现有环境。

## 验收不能只看总数

先独立标注保留的测试图片，再将预测与每个真实个体一对一匹配，分别报告检出正确数TP、误检FP、漏检FN、精确率和召回率，同时记录整图无误检且无漏检的比例。总数误差只作补充；漏一只加一个误检不抵消为正确结果。

按简单俯视、明显大小差异、接触、遮挡、裁边分别统计，训练与测试按原始照片来源隔离。分类分数、检测分数、多模型总数一致和同图多次输出一致，都不等于逐实例正确。若必须保证每张图不漏不重，需要限定可判定的拍摄条件，并对不确定结果复核；任意遮挡照片不能据此给出库存总数。
