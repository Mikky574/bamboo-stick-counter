# 点选目标示例后重新计数

## 页面使用

1. 上传原图，照常点击“开始识别”；也可以直接打开预览上方的“点选示例”开关。
2. 在1–3个不同目标中心单击或轻触。例如数木杆端面时，点端面的中心，不点杆身或两端面之间的缝。蓝色E1–E3方框表示你提供的示例，绿色点表示模型预测，两者互相独立。
3. 点击已有蓝框或对应的示例缩略图，选择要调整的示例。拖动蓝框内部移动中心，拖动四角调整范围；也可用“范围大小”滑块或加减按钮微调。每个示例独立保留自己的位置和大小，不会同时修改其他示例。
4. 对照局部放大预览，让蓝框尽量包住一个完整目标，避免包括相邻对象。预览里的蓝框对应实际参考范围，图边以外的部分裁剪到图内。范围数值为原图像素，放大画面不会改变这些数值。
5. 目标太小时，使用图片下方的加减按钮放大；放大后可开启“移动画面”拖动查看其他位置，再关闭它继续选点。“适应”恢复完整图片视图。
6. 点击“按 N 个示例重新计数”。模型用这些区域重新查找整张图中的相似目标。选点、移动、调范围、查看裁剪预览和缩放均只更新界面，不触发模型推理；提交重数后才调用模型。

“收起调整”只收起编辑工具，保留示例、待重数提醒和重数按钮，图片恢复普通查看交互。需要继续修改时点击“调整示例”。收起不会自动重数；修改示例后旧数量暂时保留，并显示“示例已调整，重数后更新结果”。

支持撤销一次新增、移动、范围调整、删除或清空；“删除当前”只删除选中的示例。画布获得焦点时可用Ctrl/Cmd+Z撤销、Delete/Backspace删除当前示例、Enter按示例重数；拖动中按Esc取消本次拖动，其他时候按Esc收起调整。表单控件保留自身的按键操作。

运行期间锁定选点、视图调整和上传；失败或超时保留原图与示例，换图会清空示例。收起调整或关闭点选后可按住查看原图，鼠标悬停查看预测的局部放大。默认“开始识别”按钮始终只发送图片，不会自动使用仍留在页面上的选点；示例重数按钮才提交视觉参考。

这不需要训练、不会保存一个新模型，也不是“选了三个就给总数加三”。选点范围过大、只含纹理片段、三个目标外观过于相似或与其他目标大小差别明显，都可能产生不同结果。不能保证点选后比自动路径更准；自动端面检查和手动通用示例是两条不同路径。结果仍为候选，必须核对漏检和重复。

## 后端和API

默认请求不变：

```json
{"image":"data:image/jpeg;base64,..."}
```

可选点示例请求：

```json
{
  "image":"data:image/jpeg;base64,...",
  "engine":"smart",
  "exemplar_points":[
    {"x":417,"y":210,"diameter":56},
    {"x":411,"y":420,"diameter":64}
  ]
}
```

坐标必须对应上传图片解码后的原尺寸。支持1–3个点，每个直径8–400，数字必须有限、不能是布尔值，点必须在图内，重复点、空数组、null和错误格式返回400，不启动模型。网页和API均支持逐点提供独立直径；网页缩放和平移仅改变显示，不重新采样上传图片或更改原图坐标。调用显式 `engine=countgdpp, device=cpu` 可在原隔离CPU worker验证同样的视觉流程；默认smart仍遵循原GPU准入和资源不足拒绝策略。

`point_prompts.py`将点和直径换算为裁剪到图内的方框。隔离CountGD++ worker将方框按实际预处理后的宽高分别缩放，直接送入一次视觉示例前向；不先跑场景分类，不使用自动示例，不尝试其他类别。通用文字 `object` 避免旧类别文字覆盖用户所选目标。候选保留0.23默认阈值，使用IoU 0.7去除高度重合框，不使用“均匀端面”的中心间距假设，因为用户也可能选择重叠昆虫等对象。

返回 `meta.mode=user_point_visual_exemplars`、`manual_exemplars=true`、`user_exemplar_count`、`exemplar_points`、`pseudo_exemplar_count=0` 和原图 `exemplars`，便于核对视觉输入。`reference_source=current_request_user_points`区分主动用户输入与离线评估。`count_kind=exemplar_candidates`、`count_is_total=false`、`review_required=true`始终保留；无检测返回 `count=null`，不把失败显示为0。

单次worker使用临时JSON文件传选点，常驻worker使用同一JSON-lines任务传输；不新增模型环境或常驻GPU实例。CLI可用 `--exemplar-points-file`读取同格式点数组。Web日志不记录图片、base64或这些点的坐标。

## 本次图片核验范围

本地两张图片先独立逐排人工标注可见端面，参考只用于评估，不作为自动计数或点示例输入。模型匹配后分别检查正确检出、误检和漏检，不能只对总数。

第一张斜视木杆束原来返回97候选，其中混入侧身框且有漏检。增加有限端面确认后，当前原图API输出91，与91个独立参考一对一匹配。第二张正面木杆束维持50，50个参考全部匹配。这是两张开发照片的结果，不是对所有图片的准确率承诺。

手动示例路径另做真实API验证：正面图的示例得到50并逐个匹配；第一张随示例位置变化仍有漏检和误检，因此没有宣称点选后必然准确。自动路径的端面限制不强加给任意用户示例。
