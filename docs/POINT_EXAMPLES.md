# 点选目标示例后重新计数

## 页面使用

1. 上传原图，照常点击“开始识别”；也可以直接打开预览上方的“点选示例”开关。
2. 在正例标签中，点选1–3个要数的目标中心。例如数木杆端面时，点端面的中心，不点杆身或两端面之间的缝。蓝色E1–E3方框表示正例，绿色点表示模型预测，两者互相独立。
3. 如果模型把某种相似对象也算进去，可切到反例标签，点选1–3个不要数的对象，显示为红色N1–N3方框。例如希望只数端面时，可把被误算的杆身区域作为反例。使用反例前必须至少选一个正例；不需要反例时留空即可。
4. 点击已有参考框或对应的示例缩略图，选择要调整的示例。拖动框内部移动中心，拖动四角调整范围；也可用“范围大小”滑块或加减按钮微调。正例和反例都独立保留自己的位置和大小，不会同时修改其他示例。
5. 对照局部放大预览，让参考框尽量包住一个完整对象，避免同时包括要数和不要数的对象。预览里的框对应实际参考范围，图边以外的部分裁剪到图内。范围数值为原图像素，放大画面不会改变这些数值。
6. 目标太小时，使用图片下方的加减按钮放大；放大后可开启“移动画面”拖动查看其他位置，再关闭它继续选点。“适应”恢复完整图片视图。
7. 点击示例重数按钮。模型用正例查找整张图中的相似目标，并在提供反例时参考它们排除不想统计的对象。选点、切换正反例、移动、调范围、查看裁剪预览和缩放均只更新界面，不触发模型推理；提交重数后才调用模型。

“收起调整”只收起编辑工具，保留示例、待重数提醒和重数按钮，图片恢复普通查看交互。需要继续修改时点击“调整示例”。收起不会自动重数；修改示例后旧数量暂时保留，并显示“示例已调整，重数后更新结果”。

支持撤销一次新增、移动、范围调整、删除或清空；“删除当前”只删除选中的示例。画布获得焦点时可用Ctrl/Cmd+Z撤销、Delete/Backspace删除当前示例、Enter按示例重数；拖动中按Esc取消本次拖动，其他时候按Esc收起调整。表单控件保留自身的按键操作。

运行期间锁定选点、视图调整和上传；失败或超时保留原图与示例，换图会清空示例。收起调整或关闭点选后可按住查看原图，鼠标悬停查看预测的局部放大。默认“开始识别”按钮始终只发送图片，不会自动使用仍留在页面上的选点；示例重数按钮才提交视觉参考。

这不需要训练、不会保存一个新模型，也不是“选了三个就给总数加三”。反例是整张图的视觉排除提示，不是只抹掉所点位置的一个标记，也不是从总数中减去反例个数。模型可能漏掉相似的误检，也可能误删本来该数的对象；提供反例后候选数量不保证只减不增。

选点范围过大、只含纹理片段、示例外观过于相似或与其他目标大小差别明显，都可能产生不同结果。不能保证点选后比自动路径更准；自动端面检查和手动通用示例是两条不同路径。结果仍为候选，必须核对漏检和重复。

## 后端和API

默认请求不变：

```json
{"image":"data:image/jpeg;base64,..."}
```

只提供正例的请求保持不变：

```json
{
  "image":"data:image/jpeg;base64,...",
  "engine":"smart",
  "exemplar_points":[
    {"x":417,"y":210,"diameter":56},
    {"x":411,"y":420,"diameter":64}
  ]
}
```

可选增加反例：

```json
{
  "image":"data:image/jpeg;base64,...",
  "engine":"smart",
  "exemplar_points":[{"x":417,"y":210,"diameter":56}],
  "negative_exemplar_points":[{"x":175,"y":260,"diameter":48}]
}
```

坐标必须对应上传图片解码后的原尺寸。正例 `exemplar_points` 和可选反例 `negative_exemplar_points` 各支持1–3个点，每个直径8–400，数字必须有限、不能是布尔值，点必须在图内。字段存在但内容为 `[]`、`null` 或错误格式，以及组内重复点，均返回400，不启动模型；不提供反例时省略反例字段。反例必须与至少一个正例同时提交，任意正例与反例中心距离小于2个原图像素也会被拒绝，不能把同一位置同时当作要数和不要数。

网页和API均支持逐点提供独立直径；网页缩放和平移仅改变显示，不重新采样上传图片或更改原图坐标。调用显式 `engine=countgdpp, device=cpu` 可在原隔离CPU worker验证同样的视觉流程；默认smart仍遵循原GPU准入和资源不足拒绝策略。

`point_prompts.py`将点和直径换算为裁剪到图内的方框。隔离CountGD++ worker将方框按实际预处理后的宽高分别缩放，直接送入一次视觉示例前向；不先跑场景分类，不使用自动示例，不尝试其他类别。不提供反例时保留原有单正例组流程，使用通用文字 `object`、0.23默认候选阈值和IoU 0.7去除高度重合框，不使用“均匀端面”的中心间距假设，因为用户也可能选择重叠昆虫等对象。

提供反例时，将当前图片的1–3个反例作为同一负例组，使用CountGD++原生负视觉示例输入，与正例在同一次模型前向中参与判断，复用原有权重，无需训练。提示结构为 `object . .`：正例属于第一个标签，反例属于第二个标签。按照模型输出 `input_ids` 的首个分隔句点划分正负标签分数，仅保留正例分数大于0.23且大于反例分数的候选，再按正例分数做重合框去重。此处不是按参考点距离抹除检测，也不是用反例数量减总数。

同一次前向不代表与纯正例相同的计算量：原生负例路径会增加一组图像特征提取，可能增加耗时和工作显存；模型常驻和权重复用不等于显存固定上限。

返回 `meta.mode=user_point_visual_exemplars`、`manual_exemplars=true`、`user_exemplar_count`、`exemplar_points`、`pseudo_exemplar_count=0` 和原图 `exemplars`，便于核对视觉输入。`reference_source=current_request_user_points`区分主动用户输入与离线评估。`count_kind=exemplar_candidates`、`count_is_total=false`、`review_required=true`始终保留；无检测返回 `count=null`，不把失败显示为0。

提供反例时还返回原图 `negative_exemplars` 方框及 `meta.negative_exemplar_points`、`user_negative_exemplar_count`、`negative_exemplar_method=native_negative_visual_tokens`。`negative_rejected_prediction_count` 是模型同次前向中在正负分数竞争时淘汰的原始候选数，尚未做去重，不能当成准确排除的物体数，也不能用它从旧结果直接减数。

单次worker使用临时JSON文件传选点，常驻worker使用同一JSON-lines任务传输；不新增模型环境或常驻GPU实例。CLI使用 `--exemplar-points-file`读取正例数组，可选 `--negative-exemplar-points-file`读取同格式反例数组。Web日志不记录图片、base64或这些点的坐标。

## 本次图片核验范围

本地两张图片先独立逐排人工标注可见端面，参考只用于评估，不作为自动计数或点示例输入。模型匹配后分别检查正确检出、误检和漏检，不能只对总数。

第一张斜视木杆束原来返回97候选，其中混入侧身框且有漏检。增加有限端面确认后，当前原图API输出91，与91个独立参考一对一匹配。第二张正面木杆束维持50，50个参考全部匹配。这是两张开发照片的结果，不是对所有图片的准确率承诺。

手动示例路径另做真实API验证：正面图的示例得到50并逐个匹配；第一张随示例位置变化仍有漏检和误检，因此没有宣称点选后必然准确。自动路径的端面限制不强加给任意用户示例。

反例路径已验证两组示例进入真实GPU推理，但实测也会过度排除或增加误检：混色玻璃珠仍有颜色混入，黑球作为正例时曾返回无可靠结果；正面木杆图加一处杆身反例后由50变51。清楚区分的草莓／蓝莓图保持16，但不证明其他场景准确。建议与清空反例后的结果对照；无结果时调整位置、范围或换代表性反例，不把它当作数量为零。详细验证及离线对照见[验证说明](VALIDATION.md)。

无权重回归包括 `verify_point_prompts.py`、`verify_end_face_review.py` 以及 `node verify_frontend.cjs`，分别检查像素变换、单次视觉前向、进程传输、范围限制和页面交互。照片、人工参考与调试输出保留在本地 `outputs/point_prompt_20261019/`，不进入模型权重或公开源码。
